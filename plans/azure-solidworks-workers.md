The controller accepts only the current assignment/generation of a noncancelled job, validates manifests, then conditionally commits the task result. A late completion never overwrites accepted state.

All job, assignment, worker and artifact manifests also carry `agent_version` and integer `farm_protocol_version=1`; incompatible versions fail admission, never silently reinterpret a schema.

Worker, assignment, task receipt and result manifest also carry integer `desktop_generation`, captured at task start and completion. Session-change events invalidate the in-flight generation as described below.

Assign ready tasks FIFO by job creation, then stable task name; assign at most one task per VM. Prefer a ready VM already holding the job's source, without overriding older jobs indefinitely. Count `starting` workers as capacity; start only the deficit between runnable backlog and available/starting workers, maximum five. Structural dependencies complete only after all prerequisites succeeded. Healthy task/check failures fail that task immediately and block its descendants; allow independent already-queued branches to finish for diagnostics. No success aggregate before every requested dependency has succeeded. Do not promise exactly-once physical computation under partition: guarantee one accepted result and fence publication/reassignment.

Workers heartbeat every 15 seconds independently of COM. A **worker heartbeat** older than 90 seconds makes the controller suspect that seat; it requests deallocation and waits for Azure-confirmed deallocation before incrementing generation/reassigning. Failure to renew the controller's assignment authorization alone does **not** kill healthy COM work: the worker continues its current task under the existing crash/operation watchdog, stages its result, but accepts no new assignment and cannot have a result promoted until current ownership is reconfirmed. A restarted controller first reconciles fresh worker heartbeat, generation and persisted assignment before renewing authority; stale-controller lease data alone is not proof the worker died. Explicit cancellation/revocation still terminates the task. If Azure cannot fence a genuinely lost worker, leave its task blocked and alert; never run a second live owner. Leadership changes recover in-flight VM operations and assignments before new scheduling.

Retain existing `_exec_com` crash recovery for watchdog exits 86/87 and disconnects. After those attempts are exhausted, classify as infrastructure failure, quarantine that seat and allow **one** replacement assignment on a different healthy VM. Never retry a deterministic healthy geometry/gate failure on other VMs. Store separate COM retry and farm assignment counts to avoid multiplying them invisibly.
