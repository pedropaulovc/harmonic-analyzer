# How I used AI to build a 19th-century computer

The fifth deliverable: an honest account of using LLM coding agents to
reverse-engineer, model, verify and document a machine — what worked, what
wasted weeks, and what I would not do again.

Publishable as a companion book, an appendix to the main book, or a blog
series. **Decide the format after the material exists**, not before — the
material will tell you which it is.

## Why this is worth writing

This repo is an unusually complete artefact of AI-assisted engineering:

- ~115 CAD parts generated by Python scripts written almost entirely with
  agents, driving a COM API that is famously badly covered by training data.
- A build pipeline, a verification suite, a remote cache, a watchdog and full
  OpenTelemetry instrumentation — all of it agent-built, and all of it in git
  history with the reasoning attached.
- **Hundreds of PRs with automated review comments**, so the failures are
  documented in public rather than remembered charitably.
- `memory/` — 130+ files of hard-won findings, each one usually a bug that cost
  real time.
- `AGENTS.md` sections that read as postmortems: mechanisms built, used, then
  deleted, with the reason recorded.

Almost nobody writing about AI-assisted engineering has evidence at this
resolution. Most of it is vibes. This can be receipts.

## The honesty bar

The whole value is credibility. So:

- **Every claim gets a citation** — a commit, a PR, a `memory/` file, a
  telemetry number. If it can't be cited, it doesn't go in.
- **Failures get the same space as successes.** More, probably. The successes
  are boring and everyone claims them.
- **No token counts, hours or costs unless they're measured.** `memory/usage.jsonl`
  and `cad/out/reports/telemetry/` have real numbers; use those.
- **No "AI wrote 90% of this"-style claims.** Say what it actually did, at what
  granularity, with what supervision.

## The thesis, provisionally

Agents were extraordinary at the parts with a **tight, mechanical feedback
loop** — a gate that fails, a test that goes red, a render you can look at —
and dangerous at the parts without one. Most of the wasted time in this project
came from confident work built on an unverified premise, not from bad code.

That thesis has to survive contact with the evidence. If the receipts say
otherwise, the thesis changes.
