**Post-release reconciliation wrinkle (new):** the first `doit` after a `release`/full build is NOT a no-op — every assembly cache-MISSES and REFRESHES once (~14 min for all 8) before settling to a clean no-op. Root cause: the late release stages (frame/top assembly build) RE-SAVE their own referenced parts (7 frame parts re-stamped after the sub-assemblies recorded their dep hashes), shifting those parts' content hash so the assemblies look stale on the next run. It self-heals after one reconciling pass (2nd `doit build_bare` = 81 `--`, 0 work). Possible fix surface = relates to cache-observability issue #73. A cleaner design would auto-escalate REFRESH→FULL when a referenced part actually cache-MISSED (rebuilt), instead of attempting a doomed refresh.
