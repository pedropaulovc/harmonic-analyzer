A spring whose endpoints move is NOT a fixed-length solid. Modeling it as one rigid body and demanding it thread/fit at every assembly pose is a self-inflicted bug, NOT a physical constraint. When the harmonic-analyzer `channel-spring-installed` (a fixed-length "installed" body) interfered with tilted channel levers under the F3 amplitude drive — and overshot the summing plate (0.13 mm threading margin) when attached per-channel — the right reframe (user-prompted) is: the spring length is the wrong thing to hold constant.

**Why:** every project that animates springs makes the spring length a parameter. The model here used a fixed body, valid only at the neutral lever tilt (cosmetic-only by accident).

**How to apply:** drive the spring's free length (and often coil pitch) from the live mount-to-mount distance.
1. **Equation/global-variable-driven length** — dominant fix: helix height = distance between the two mounts (global var or in-context ref); rebuilds to fit when the assembly moves.
2. **Configurations / design table** — discrete free lengths, each instance picks its config (`place_component(configuration=...)`); good for a handful of lengths (the channel bank needs ~10 distinct installed lengths).
3. **Motion force-springs + hidden/cosmetic geometry** — for dynamics, an Add-Spring force entity, body hidden/shown-at-rest only.
4. Flexible subassembly; 5. cosmetic/suppress (the lazy version).

For the channel bank: add a `free_length`/stretch param to `build_channel_spring_installed.py`, set it per channel from the lever-tip→plate distance the loop already computes, place each instance at its length inside the channel loop (replacing seed+pattern). Bushings stay patterned (length-independent). Relates to [[professionalize-plan-status]] F3 + the F5 computed-summation policy ([[harmonic-analyzer-project]]).

**DE-RISK PROTO RESULT (build_summation_proto.py, throwaway rig, 2026-06-15).** Tested whether to MATE each spring end-to-end (the proposed `summation` co-location reorg) vs keep it grounded-at-measured-length. Findings, each proven live in SW:
- ✓ **Measured-length write works**: body = gap − top_lead − bottom_lead; with body 63.05 the two eyes land at EXACTLY the 74.15 eye-c2c (top [50,65.05,0], bottom [50,−9.1,0]). `build_spring(eye_axes=True)` now RETURNS the baked axis names (`bottom_lead_axis`/`top_eye_axis` = Axis1/Axis2).
- ✓ **Top hinge works**: `concentric(spring top-eye Axis2, bore_axis_ref(pin OD point))` against a grounded horizontal pivot-shaft pin. (An assembly-level CREATED axis does NOT select by bare name in AddMate5 — principal planes do; use a real part face or `_entity_ref` component axis.)
- ✗ **Pure axis/plane bottom locks OVER-DEFINE**: `distance(bottom-lead axis ↔ Front Plane)` after the hinge → "mate over-defines the assembly". Axis-to-plane (and plane-plane) distance/coincident mates carry an implicit parallel/rotation constraint that's redundant once the concentric hinge fixed orientation. A fixed-length link between a hinge and a hole needs a PURELY-TRANSLATIONAL free-end lock = a **point-on-axis** or point-to-plane mate, i.e. a baked eye-centre **RefPoint** (exactly the connecting-rod idiom, `build_motion_study._add_ring_centre_point`: arc_center of the Ø51 bore edge → point-on-cam-axis). The spring EYE CENTRE sits in empty space (the 270° loop surrounds it) with NO clean circular edge, so arc_center gives wire-section caps, not the eye centre — the reorg would have to MODEL a mate-reference at the eye (closed-ring edge / reference-circle feature / sketch-point RefPoint).
- **Conclusion / recommended path**: full end-to-end mating is hard AND unnecessary for STATIC config snapshots (springs are cosmetic; the summation is computed, not simulated — [[harmonic-analyzer-project]] F5). Prefer **grounded-at-measured-length**: per channel compute the lever-tab (at its F3 amplitude pose) → plate-hole line in the channel frame, build each `channel-spring-installed` at that gap length, and `place_component(ground=True)` oriented along that line. 0-DOF trivially, no poke, no reorg, no eye RefPoint. This is the F3-interference fix (task #10).
