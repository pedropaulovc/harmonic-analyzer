## Exact discrepancy

```text

```

Native display data contains two ordered text runs: the first ends with
`DFT;` followed by one ASCII space (U+0020), and the second is `mask all bores`.
Their Y origins are
0.03626423529842122 and 0.03308923533679171 m. Concatenation equals the complete
native text exactly, including its space.

Both actual PDFs return one unique matching range, index 156 / count 63.
Only absolute character indices 203 and 204 are generated by PDFium: CR and LF,
each with the zero-area box `(954.1290283203125, 104.75039672851562,
954.1290283203125, 104.75039672851562)` points. They occur precisely between
the two complete native runs. No printed letter, digit, punctuation or space is
missing. PDFium explicitly distinguishes generated characters from PDF content;
the wrapper also documents CRLF extraction. See the official
[FPDFText_IsGenerated contract](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/public/fpdf_text.h)
and [PdfTextPage text API](https://pypdfium2.readthedocs.io/en/stable/python_api.html#pypdfium2.PdfTextPage.get_text_range).

The correction records generated flags without changing raw PDF text or boxes.
Field reconciliation requires exact full native text, exact ordered native run
values, distinct descending native text lines, and only generated zero-area CRLF
at those boundaries. It does not strip arbitrary whitespace, replace characters,
or relax cell-fit/collision tests. The existing repeated-ASCII-space policy and
separately witnessed angular-symbol decoder are unchanged.
